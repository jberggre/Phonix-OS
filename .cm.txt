Make a failed pack replace leave nothing behind

A failed install could strand a `*.part` inside the guest tree, and it deleted the destination before
renaming the replacement into place, so a replace that failed took a working pack with it. Both are
wrong for the same reason: a staging name must never outlive the attempt, and nothing that already
works may be destroyed before its replacement exists.

`verified()` also defaulted to the wider catalogue and the view model called it without one, so a
release build could report a debug-only control as installed; it now defaults to the shipped table
and the view model passes the catalogue it resolved from.
